# Словарь тестировщика

## Термины (одной строкой)
- **Тест** — проверка: факт = ожид.
- **Тест-кейс** — подробная проверка: ID, шаги, данные, ожид. результат. Одна проверка = один кейс.
- **Чек-лист** — список «что проверить», вычёркиваем сделанное. Быстро, но чужой может не понять.
- **Тест-план** — как тестируем релиз: что/что нет, подход, окружения, сроки, риски. Пишет QA-лид.
- **Test Suite** — набор тестов.
- **Баг-репорт** — документ об ошибке: заголовок, шаги, факт vs ожид, видео, окружение.
- **Ошибка (error)** — у разработчика в коде.
- **Дефект (defect)** — ошибка в общем коде. Ищешь дефекты, заводишь баги.
- **Severity** — влияние на систему: trivial / minor / major / critical / blocker.
- **Priority** — влияние на бизнес: low / medium / high. Кнопка «Оплатить» пропала: severity critical, priority high.
- **Смок** — жив ли продукт (5–15 мин). Нет → стоп.
- **Санити** — углублённо модуль или проверка после мелкого фикса.
- **Регресс** — старое не сломалось после нового. Перед релизом.
- **Ретест** — конкретный баг исправлен.
- **Позитив** — верные данные → верный ответ. **Негатив** — неверные → понятная ошибка.
- **Статика** — без запуска (требования, код). **Динамика** — тыкаем живое.
- **Black-box** — как пользователь. **White-box** — знаем код. **Gray-box** — БД/логи/API без кода.
- **Верификация** — делаем правильно? (по ТЗ). **Валидация** — делаем нужное? (пользователю).
- **SDLC** — жизнь продукта: идея → требования → дизайн → разработка → тестирование → релиз → поддержка.
- **STLC** — жизнь тестирования: анализ → план → кейсы → окружение → прогон → отчёт.
- **Окружения** — dev (ломаем) / test-QA (тестируем) / stage (финалка) / prod (юзеры, не трогаем).
- **Клиент** — браузер/приложение. **Сервер** — считает. **БД** — хранит.
- **HTTP** — правила общения клиента и сервера. **Request** — запрос, **Response** — ответ.
- **Статусы** — 2xx ок (200, 201 создан); 3xx редирект; 4xx твоя вина (400, 401, 403, 404); 5xx сервер упал.
- **GET** — получить (без body). **POST** — передать (с body). **PUT** — заменить целиком. **PATCH** — подправить часть. **DELETE** — удалить.
- **Body** — данные в запросе.
- **Идемпотентность** — повтор = тот же результат. Все, кроме POST (PATCH — зависит).
- **Кэш** — временное хранилище (картинки/CSS/JS). Чистить: Ctrl+F5.
- **Куки** — ярлык пользователя: сессия, корзина, язык, аналитика.
- **Session ID** — метка залогиненного.
- **API** — договорённость программ. **Postman** — шлём запросы. **Swagger** — доки методов.
- **REST** — стиль API: понятные имена, гибкий.
- **Монолит** — всё в одном; упало — легло всё. **Микросервисы** — сервисы отдельно; упал один — остальные живы.
- **Балансировщик** — раскидывает нагрузку по серверам.
- **Тонкий клиент** — считает сервер. **Толстый** — считает сам.
- **Классы эквивалентности** — делим значения на группы, берём по одному.
- **Граничные** — граница ±1. Full value (3 проверки) тщательнее two value (2).
- **Decision table** — таблица «условия → результат» (купон/корзина).
- **Состояния** — создан → оплачен → доставка → доставлен; прыжки = баг.
- **Pairwise** — минимум комбинаций, где каждая пара встречается (8 → 4).
- **Предугадывание** — как сломает юзер (пустое, пробелы, длинное).
- **Сценарий** — путь целиком от начала до конца.
- **Пирамида** — unit → integration → system → E2E (дороже и дольше вверх).
- **TMS** — система хранения доков (TestRail, Test IT, Jira).
- **Логи** — история событий системы.
- **2FA** — второй код (SMS/Face ID).
- **Идентификация** — кто ты (логин). **Аутентификация** — точно ты (пароль). **Авторизация** — что можно (права).
- **Локализация** — язык + валюта + даты под страну.
- **UI** — как выглядит. **UX** — удобно ли.
- **Performance** — скорость. **Стресс** — резко ломаем. **Нагрузка** — постепенно. **Стабильность** — держится.
- **Плавающий баг** — не воспроизводится повторно. Пометка в репорте.
- **Воспроизводимость** — всегда ли падает.
- **Предусловия** — что сделать до теста.
- **Окружение в репорте** — ОС + браузер + стенд.

## Словарь запретных слов (качественный отчёт)
- быстро / медленно → секунды (замер).
- нормально / хорошо / плохо → факт + результат проверки.
- идеально / качественно → цифры: время, покрытие, статусы.
- удобно / неудобно → клики, понятность ошибок.
- иногда / часто / редко → X из Y попыток.
- большой / маленький → точное значение.
- скоро / потом → дата и время.
- стабильно / нестабильно → условия + повторяемость.
- правильно / неправильно (без ссылки) → пункт требований.
- вроде / кажется → проверить и дать факт.

Правило: **факт + число + условия**. Нет числа — это мнение, а не результат.

## Обязательные слова профессионального отчёта
Эти слова есть почти в каждом качественном отчёте. Нет их — отчёт неполный:
- **Окружение** — где проверял (ОС, браузер, стенд, сборка). Без него баг невоспроизводим.
- **Шаги воспроизведения** — пронумерованные действия с конкретными данными.
- **Ожидаемый результат** — из требований (цитата). Нет требований — пиши ориентир.
- **Фактический результат** — что вышло на деле, дословно (текст ошибки — текстом).
- **Расходящийся шаг** — номер шага, где ожид ≠ факт.
- **Воспроизводимость** — всегда / 3 из 3 / плавающий.
- **Severity** — влияние на систему (ставишь ты). **Priority** — скорость исправления (согласует лид).
- **Статус** — где баг сейчас (Новый / В работе / Закрыт…).
- **Вложения** — видео, скрин, логи. Видео — обязательно.
- **Предусловия** — что сделано до теста (залогинен, открыта страница X).
- **Набор данных №** — вместо приватных данных (карты, телефоны — только номером набора).
- **Дата + пояс** — когда нашёл (Душанбе). **Версия/сборка** — что тестировал.
- **Проверено / Не проверено** — что успел, а что нет (честно).
- **Ограничения** — чего не видел («только frontend», «без доступа к БД»).
- **Итого цифрами** — время, найдено, исправлено, не исправлено.
